# R3 depth wave acceptance

This wave expands 28 existing skills and preserves all 100 starter IDs, 64 skill IDs, 20 workflow records and the original eight R2 depth assets. Counts distinguish authored content from executed model performance.

## What the checks establish

The optional evaluator checks supplied JSON, arithmetic, identity, state and declared evidence scope. It does not call Muse, inspect a real inbox, run a candidate program, create a booking, change care instructions or authenticate provider evidence. Meeting extraction and lecture mapping use separately authored adjudication oracles; those oracles are not placed in challenge packets. Prose and resume checks cover explicit protected facts, not complete semantic equivalence.

For each of 28 skills there are standard, edge and recovery examples. These 84 public regression cases are not hidden holdouts. Plain, upstream and candidate packets receive identical task bytes. Candidate packets exclude both worked examples and evaluator answers. An upstream arm needs the actual pinned package and required references, not only a URL. Missing dependencies make that arm unqualified rather than a competitor failure.

## Gates

Run the collection checks, R3 source/behavior tests and full parent suite. Reopen all 100 starter archives and verify every manifest entry; exercise the packaged evaluator outside the repository. On A/B/C qualify the same frozen source, record skips and compare source identity to live private main. Preserve existing unrelated work. Public release is not authorized by a local export or green CI.

Actual matched Muse results remain NOT_RUN until an authenticated supported session has produced recorded outputs under the stated protocol. A second OS running the same tests is cross-platform verification, not independent semantic judgment. A mechanically valid answer does not establish usefulness or broad superiority.

## Next wave

Twenty-eight original foundation skills remain. Do not expand the catalog before comparable depth and task evidence are developed for them. Do not rebuild the original R2 collection or erase its evidence.

## Regression review findings

Input-change checks found that the first weekly-capacity evaluator ignored prerequisite IDs. The corrected evaluator rejects unknown prerequisites and blocks only tasks whose prerequisites are unmet. Original authored example answers are never read as an oracle by R3 calculators. Altered gold examples cannot change their verdicts. The original collection FIFO test now isolates its child interpreter from site startup while retaining the same three-second refusal deadline.
