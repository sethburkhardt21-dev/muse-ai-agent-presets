# Scope a Useful Next Result — operational depth

Read only the branch needed for the current task. These are working methods, not a demand for additional approvals on ordinary reading or drafting.

## Domain method

Treat scope as a dependency and information problem, not a demand to interview the user again. Identify the concrete result, the context already available, the reversible work that can begin, and any step whose outcome changes an external system. Tool availability, permission and suitability are separate properties: an available email tool is not approval to send.

Choose the smallest specialization that can produce the requested artifact. A bounded answer does not need a committee of agents. Partition missing inputs into essential blockers and optional refinements; a missing optional preference should not prevent a useful first result. Route independent work around a localized tool gap without substituting an unauthorized provider.

## Output contract

Return the immediate result or the first bounded work product, followed by only the unresolved decisions that matter. For multi-step work preserve task IDs, dependencies, completed artifacts, available tools and authorized effects. Report held actions separately from ready read/draft work; a plan is not an execution receipt.

## Choose the right action

### The request already contains a usable brief.
Start producing the requested result using the supplied constraints; record assumptions that can be changed cheaply.

**Avoid:** Do not reopen settled decisions or demand an installation ritual.

### A required tool is absent but source material is supplied.
Complete the source-based analysis and identify the exact external verification that remains.

**Avoid:** Do not pretend a plugin label is a callable tool or that every task must stop.

### A consequential action lacks authorization.
Prepare the exact proposed action and hold that effect; continue independent authorized work.

**Avoid:** Do not convert permission to draft into permission to send or publish.

### Several specialists could help.
Select by the result and acceptance criteria, not by the largest role title; add another specialist only for a distinct gap.

**Avoid:** Do not duplicate the same task across workers without a comparison purpose.

### An earlier task appears completed.
Reopen its artifact and establish current validity before using it as a dependency.

**Avoid:** Do not restart completed work merely because the chat or process restarted.

## Worked example (authored, synthetic)

**Input:** Draft a report, then send it after approval. The mail tool exists, but sending is not yet approved.

**Method:** Separate the artifact from its delivery and retain the draft-to-send dependency.

**Result:** Draft the report now. Hold sending for the exact recipient and approved content; do not call the entire request blocked.

## Edge or recovery example 1 (authored, synthetic)

**Input:** The draft was completed in the previous session and approval to send is now explicit.

**Method:** Read the saved draft and confirm that its content and recipient still match the approval.

**Result:** Reuse the draft. Perform the authorized delivery once through the available provider and report its actual result.

## Failure diagnosis

### The assistant asks the same question repeatedly.
**Likely cause:** The brief was not reconciled with available context.

**Repair:** Extract settled decisions and ask only for a missing answer that changes the artifact.

**Recheck:** The next action uses existing answers.

### Every step is held by one unavailable tool.
**Likely cause:** Dependencies were flattened into a single serial chain.

**Repair:** Separate effect-dependent steps from independent read, draft or calculation work.

**Recheck:** At least the feasible independent result is delivered.

### A task is labeled done without an artifact.
**Likely cause:** Intent was confused with effect.

**Repair:** Inspect the real output and downgrade only the unsupported claim.

**Recheck:** Every completed task points to an observed result.

## Preserve for the next turn

Preserve settled scope, source/artifact identities, available tool names, dependency IDs, completed work and the original authorization boundary. Resume at the first unfinished ready action, not at a new discovery interview.
