# Expansion roadmap

## Product shape

Keep 100 understandable starter choices at the front. Grow the reusable skill library behind them through progressive disclosure and precise routing. A user should not need to paste thousands of instructions or select among near-identical roles.

## Scale target: 6,000 distinct admitted skills

This is an aspirational catalog target, not a delivered count or a promise of superiority. The pinned broad Muse source advertised 2,648 entries while its tree contained 2,683 `SKILL.md` files. Neither count establishes distinct, high-quality capabilities. Twice those raw numbers would be 5,296 or 5,366; 6,000 is a round planning target with room for deduplication and genuine new coverage. Do not publish a “twice as capable” claim from counts.

The first collection contains 64 authored skills, 100 starters and 20 recipes. No other source candidates are included in that count.

## Ordered milestones

| Milestone | Deliverable | Acceptance |
|---|---|---|
| Foundation | Source ledger, 100 starters, 64 initial skills, recipes and offline selector | Deterministic source checks, useful examples, no hidden runtime or account effects. |
| Pilot quality | Eight representative starter comparisons | Actual outputs, matched conditions, failure cases, preserved losses/ties and a reviewed improvement decision. |
| Intake and deduplication | Pinned upstream item inventory across Muse, Grok Bot and relevant open skill collections | Per-item rights and provenance; reference-only holds; no candidate counted as admitted. |
| Depth batches | 32–64 distinct skills per domain batch | Concrete inputs, outputs, examples, recovery and outcome-based evaluation; repair existing weak skills before expansion. |
| Product integration | Connect admitted skills to the existing 11 specialist families and 100 starters | Precise routing, small context footprint, versioned updates and preserved user preferences. |
| Scale | Progress toward 6,000 admitted skills only where useful coverage exists | Public count ledger, semantic deduplication and ongoing regression evaluation. |

The main improvement priorities are specificity, fewer unnecessary questions, useful output under missing optional tools, faithful source use, actual artifact inspection and recovery without duplicated effects. More rules are not automatically better.
